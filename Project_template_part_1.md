# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Система поддерживает управление отоплением.

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система поддерживает чтение с датчиков данных о температуре через запрос от сервера к датчику.

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Java
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развёртывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

**Домен «Управление отоплением»**

Домен отвечает за включение/выключение отопления.

**_Контекст управления устройствами_**

- сущности: устройство отопления
- методы: включение устройства, отключение устройства

**Домен «Мониторинг cостояния»**

Домен отслеживает и предоставляет данные о текущей температуре через датчики.

**_Контекст мониторинга состояния_**

- сущности: датчик
- методы: чтение данных датчика

### **4. Проблемы монолитного решения**

- **_Ограниченная масштабируемость_**: монолитная архитектура решения не позволяет разворачивать отдельные части системы независимо.
- **_Зависимость от центрального сервера_**: вся логика находится на сервере, взаимодействующем с устройствами. При недоступности сервера у пользователей теряется доступ к функционалу системы.
- **_Отсутствуют методы асинхронного взаимодействия_**: всё взаимодействие с системой выполняется в синхронном режиме, что влечёт за собой задержки в обработке запросов на изменение и чтение данных
- **_Недоступность при обновлении_**: для установки новой версии требуется остановка приложения.
- **_Больше времени на тестирование_**: монолитная архитектура требует более тщательно проводить тестирование, т.к. изменение во одном из компонентов системы может повлиять на работоспособность системы вцелом.
- **_Отсутствует поддержка Plug&Play_**: пользователь не может подключить и настроить систему самостоятельно, требуется вызов специалиста.
